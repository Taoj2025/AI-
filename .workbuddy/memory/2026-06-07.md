## Docker 配置修复

### 问题
- docker-compose.yml 中各服务的 build context 指向各自目录（如 `./services/api-gateway`）
- 但 Dockerfile 中的 COPY 路径是按根目录写的，两边对不上，导致构建失败

### 修复内容

1. **docker-compose.yml** — 所有 8 个服务的 build 配置统一修改：
   - `context` 改为根目录 `.`
   - 用 `dockerfile` 字段指定各服务的 Dockerfile 相对路径

2. **api-gateway/Dockerfile** — 重写为 workspace 感知模式：
   - 复制根目录 package.json/pnpm-lock.yaml/pnpm-workspace.yaml
   - 用 `pnpm install --frozen-lockfile` 正确解析 workspace
   - 用 `pnpm --filter @resumeai/api-gateway build` 只构建目标包

3. **user-service/Dockerfile** — 同上模式重写

4. **4 个 Python 服务 Dockerfile** — 路径修正（加 `services/xxx/` 前缀）：
   - ai-dispatch/Dockerfile
   - template-service/Dockerfile
   - analytics-service/Dockerfile
   - payment-service/Dockerfile

5. **新建 .dockerignore** — 排除 node_modules/.git/dist 等

### 待验证
- 本地运行 `docker compose build` 验证构建是否通过
- Docker 环境当前不可用，需用户在本地验证

## 本地全服务启动（无 Docker）

### 解决的问题

1. **npm 缓存空间不足** — C 盘满，将 npm cache 迁移到 `D:/npm-cache`
2. **workspaces:* 协议** — 临时禁用根 workspaces 字段，让 npm 能正常安装
3. **fastify-cors 版本不存在** — `^9.0.0` 不存在，改为 `@fastify/cors@^9.0.0`
4. **Top-level await CJS 错误** — 3 个 Node.js 服务 package.json 缺少 `"type": "module"`
5. **api-gateway 通配符路由** — `*path` 改为 `*`（Fastify v4 语法）
6. **user-service require.main** — ESM 不支持 require.main，改用 `import.meta.url` 检测
7. **user-service AJV strict mode** — 添加 `ajv: { customOptions: { strict: false } }`
8. **user-service 默认端口冲突** — 默认端口 3000 改为 3004
9. **resume-service @fastify/cors 缺失** — 替换废弃的 fastify-cors
10. **resume-service 硬依赖 PostgreSQL/Redis** — 改为可选连接（无依赖时 Mock 模式启动）
11. **export-service 入口文件名** — `src.index` → `src.main`
